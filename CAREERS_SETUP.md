# Quartz Web Solutions — Careers deployment

This update adds an indexable Careers hub, three separate remote job pages, a secure careers application workflow, private admin review, Quartz-branded PDF application downloads, optional original CV uploads, and permanent deletion actions for applications, enquiries, and clients.

## 1. Deploy to Cloudflare Pages

Upload/push **the contents of this repository** to the same Cloudflare Pages project serving `quartzwebsolutions.com` and `admin.quartzwebsolutions.com`, preserving its existing `_worker.js` advanced-mode worker and Pages settings.

The existing D1 database binding named **`DB`** remains necessary. The worker creates `career_applications` and its indexes automatically; do **not** create a new D1 database or overwrite your existing CRM.

## 2. Private CV storage (required for resume uploads)

In **Cloudflare → R2 Object Storage**, create a private bucket, for example `quartz-career-cvs`. **Do not enable an R2 public domain or `r2.dev` public access** for this bucket. In your Pages project → Settings → Bindings → R2 bucket binding, select that bucket and set the **binding variable name `CV_BUCKET`**. Redeploy after adding the binding. 

- Application metadata is saved in your existing D1 `career_applications` table.
- Optional PDF, DOC and DOCX resumes (up to 5 MB) are stored in private R2 using random object keys. The filename is retained separately for downloading.
- Without `CV_BUCKET`, applications without a CV can still be received; any applicant attempting to upload a CV receives an explicit configuration error, not a false success.
- CVs download through the **authenticated admin domain only**, never a public R2 URL. Treat CV files as untrusted attachments: scan them before opening, particularly DOC/DOCX files.
- Permanent application deletion removes the original CV object and the application row from active storage. Deletion does **not** purge already-made Cloudflare backups, historical export files you downloaded or independent platform/security logs.

## 3. Security / Turnstile

Keep the current `ADMIN_LOGIN_ID`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` and `CLIENT_CREDENTIALS_SECRET`. Never place them in public HTML or source control. The application route inherits the existing Cloudflare Turnstile configuration from `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` (both needed to enable it); enable both for anti-spam protection. Admin APIs use the site's revocable login session and same-origin checks.

Set Cloudflare WAF rate limiting if public submissions grow significantly. Resume uploads are restricted by declared extension, signature and upload size but are **not** a substitute for malware scanning. Turnstile is recommended before promoting the jobs widely.

## 4. Features and URLs

Public hub: `https://quartzwebsolutions.com/careers/`

Individual indexable job pages:
- `/careers/remote-telecalling-executive/`
- `/careers/remote-business-development-executive/`
- `/careers/remote-web-developer/`

Remote positions are commission-based, open to applicants of all genders, freshers and experienced candidates from Kerala, India and internationally. English communication is preferred, not an exclusion criterion. Never advertise a guaranteed salary unless one actually exists.

Admin: sign in at `https://admin.quartzwebsolutions.com/`, then **Applications**. Each application has **Application PDF**, optional **CV**, **Mark reviewed**, and **Delete forever** actions. Both enquiry cards and client views/listings also contain permanent deletion actions. The admin must enter `DELETE FOREVER` before deletion. Client deletion removes client payments (including previously voided entries), encrypted access details and client-specific share links; public shared directories update dynamically.

Recruitment PDFs show the submitted data, the Quartz logo/header, and a confidential record marking. Uploaded resumes are downloaded separately from the application PDF to preserve the original file.

## 5. Indexing and AI discovery

The sitemap endpoint (generated by `_worker.js`) and static `sitemap.xml` include the Careers hub and the 3 job detail pages. Pages have canonical URLs, descriptive content, Open Graph tags and individually-scoped `JobPosting` structured data. `robots.txt` does not disallow them; `llms.txt` identifies the official vacancies. 

After deployment, submit `https://quartzwebsolutions.com/sitemap.xml` in **Google Search Console**. Use URL Inspection for the four career pages, confirm that they are crawlable and request indexing as needed. Optionally use [Google Rich Results Test](https://search.google.com/test/rich-results) to check job structured data. **No website code can guarantee inclusion or ranking in Google, ChatGPT, Gemini or other AI/search services**; crawling, eligibility, trust and ranking are decided by those systems. When an opening closes, remove/disable the corresponding `JobPosting` and update the sitemap to avoid misleading search results.

## 6. Test checklist after deploying

1. Open `/careers/`, select every role, and verify each individual job detail page.
2. Test an India/Kerala application, a different Indian state, and another country; check the styled searchable dropdowns.
3. Submit an application without a CV and one with a small PDF CV. Verify success and appearance in admin **Applications**.
4. Download its Quartz-branded **Application PDF** and private original **CV**. Verify PDF formatting and the PDF file content.
5. Mark an applicant reviewed, then test **Delete forever** on a test application, enquiry and client. **Back up real client records before testing permanent deletion.** Confirm R2 files disappear and the admin list is refreshed.
6. Verify `/sitemap.xml`, HTTPS and `JobPosting` structured data using Search Console or a structured-data validator.

## 7. Data retention

Define and publish a recruitment privacy/retention policy before accepting significant applicant volume. Set a reasonable retention period, use access controls and remove data you no longer need. Deleting downloaded PDFs/CVs on your computer is separate from deleting active D1/R2 data. Cloudflare backups and logs follow their own retention policies.
